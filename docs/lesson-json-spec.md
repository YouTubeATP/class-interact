# ClassInteract lesson JSON: authoring specification

**Format** `classinteract.presentation` · **Schema version** `1` · **Audience** people and AI agents who write lessons as JSON

This document is the complete reference for writing a ClassInteract lesson, including maths, code and chemistry, (a *presentation*) as one JSON document. It
is written so that an agent can produce a lesson that imports on the first try: every field, limit, default and
validation rule is listed, followed by the import API, how answers are graded, and guidance on building a good lesson.

The source of truth is the validator in [`shared/src/schema.ts`](../shared/src/schema.ts) and
[`shared/src/document.ts`](../shared/src/document.ts). A machine-readable JSON Schema is in
[`presentation.schema.json`](./presentation.schema.json) and is served at `GET /api/schema/presentation.json`.
JSON Schema cannot express the cross-field rules below (for example "the correct option must exist"), so the
importer is the final judge. Every complete example document in this file is validated by a unit test
(`shared/test/spec-examples.test.ts`).

---

## 1. Quick start

The smallest useful lesson:

```json
{
  "schemaVersion": 1,
  "title": "Fractions warm-up",
  "slides": [
    { "type": "content", "title": "Fractions", "body": "Three quick questions before we start." },
    {
      "type": "quiz",
      "question": "Which fraction is the largest?",
      "options": [{ "id": "a", "text": "1/2" }, { "id": "b", "text": "2/3" }, { "id": "c", "text": "3/5" }],
      "correctOptionId": "b",
      "explanation": "2/3 is about 0.67, 3/5 is 0.6 and 1/2 is 0.5.",
      "timeLimitSec": 30
    },
    { "type": "poll", "question": "How did that feel?", "options": [{ "text": "Easy" }, { "text": "OK" }, { "text": "Hard" }] }
  ]
}
```

To create it, send it to `POST /api/studio/presentations/import` (section 9). The response is either
`201 { "id", "warnings" }` or `422` with a list of every problem, each with a JSON path and a fix.

**Rules that catch most first attempts**

1. Unknown fields are errors, not ignored. Use the exact field names in this document (`timeLimitSec`, not `timeLimit`).
2. Each quiz `kind` has its own answer key. Fields that belong to another kind are errors (section 6.2).
3. Every id you reference (`correctOptionId`, `correctOptionIds`, `branch.below`, `confidenceFor`) must exist.
4. Text is trimmed, then length-checked. Stay well inside the limits; they are tuned for a projector.
5. `view` on a quiz is generated by the server and must never be written.

## 2. Concepts

- A **presentation** is metadata, a theme and an ordered list of **slides** (at most 150).
- A slide is either a **content** slide (something to show) or an **activity** that phones answer: `quiz`, `poll`,
  `wordcloud`, `open`, `rating`, `survey`.
- The JSON describes **content and intent**, never positions or sizes. The renderer chooses a layout for the projector
  (16:9) and for phones, and shrinks text to fit.
- The same document runs in every session mode: **standalone** (slides in order), **companion** (the presenter launches
  activities alongside their own slides) and **self-paced** (people work through on their own until a deadline). Mode is
  chosen when a session starts; it is not part of the document.
- Live-session behaviour (teams, Q&A, the understanding pulse, breaks, sound, projector look) is set per session, not
  in the document.

## 3. Document

```jsonc
{
  "format": "classinteract.presentation",   // optional; if present it must be exactly this
  "schemaVersion": 1,                        // required (see below)
  "title": "Popping boba lab",               // required
  "description": "Shown on the library card.",
  "theme": { "palette": "peach", "background": "gradient" },
  "slides": []
}
```

| Field | Type | Required | Default | Rules |
| --- | --- | --- | --- | --- |
| `format` | string | no | `"classinteract.presentation"` | Must equal `classinteract.presentation`. |
| `schemaVersion` | integer | yes | — | Use `1`. Missing → `1` is assumed with a warning. Higher than the app supports → rejected. |
| `title` | string | yes | — | 1–140 characters. |
| `description` | string | no | `""` | ≤ 600 characters. |
| `theme` | object | no | `{}` | Section 4. |
| `slides` | array | yes | — | 0–150 slides. Slide `id`s must be unique. |
| `$schema` | string | no | — | Allowed and ignored, so editors can use the JSON Schema. |

No other top-level fields are allowed.

## 4. Theme

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `palette` | enum | `"azure"` | `azure`, `lavender`, `mint`, `peach`, `rose`, `slate`. |
| `background` | enum | `"soft"` | `soft` (soft colour shapes), `plain`, `gradient`, `grid`. |
| `accent` | string | — | `#rrggbb`. Must contrast with white text at 4.5:1 or more (WCAG); light colours are rejected. A dark-mode tint is derived automatically. |
| `appearance` | enum | — | `light` or `dark`: the projector look the lesson is designed for. The presenter can override it per session. |
| `logo` | object | — | `{ "url", "alt" }`. `url` follows the image URL rules (section 5.3); `alt` ≤ 120. Shown small in a projector corner. |
| `footer` | string | — | ≤ 120 characters, shown along the bottom of the projector (course code, workshop name). |

Answer options always use the same four-colour A/B/C/D set in every theme, so choose the palette for mood, not for
answer colours.

## 5. Fields every slide shares

| Field | Type | Required | Default | Rules |
| --- | --- | --- | --- | --- |
| `id` | string | no on import | `slide-N` | `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`. Unique in the document. **Set it yourself** whenever another slide refers to this one (branches, confidence checks); generated ids depend on position. |
| `type` | enum | yes | — | `content`, `quiz`, `poll`, `wordcloud`, `open`, `rating`, `survey`. |
| `notes` | string | no | `""` | ≤ 4000. Private speaker notes, shown only on the presenter's dashboard (plain text). |
| `image` | object | no | — | Section 5.3. |
| `media` | object | no | — | Section 5.4. |

### 5.1 Fields every activity shares

Applies to `quiz`, `poll`, `wordcloud`, `open`, `rating` and `survey`.

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `timeLimitSec` | integer or `null` | `null` | 5–900. Responses close automatically when it runs out. `null` = no timer. |
| `autoOpen` | boolean | `true` | Open responses as soon as the slide is shown. `false` = the presenter presses Open. |
| `showResultsToParticipants` | boolean | per type (below) | Phones may see results once the presenter shows them. |
| `liveResults` | boolean | `true` | Not on quizzes. Results update on the projector while answers arrive; `false` keeps them hidden until shown. |

`showResultsToParticipants` defaults: quiz `true`, poll `true`, wordcloud `true`, rating `true`, open `false`, survey `false`.

### 5.2 Ids inside slides

Option, item, pair, region and survey-question ids match `^[A-Za-z0-9_-]{1,32}$` and must be unique within their
list. They are optional on import and generated when missing: options and items `o1`, `o2`…, pairs `p1`…, regions
`r1`…, survey questions `q1`…. **Give options explicit ids** (`"a"`, `"b"`…) whenever you set `correctOptionId` or
`correctOptionIds`, so the answer key cannot point at the wrong option.

### 5.3 `image`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `url` | string | required | ≤ 2000. `https://…` or `http://…` (no username or password in the URL), or a server path starting with `/` (an uploaded `/uploads/…` file or a bundled `/templates/…` picture). |
| `alt` | string | `""` | ≤ 240. Describe the picture; it is read by screen readers and shown if the image fails. Always write it. |
| `fit` | enum | `"cover"` | `cover` (fill and crop) or `contain` (show the whole picture). Use `contain` for diagrams and anything used in a hotspot question. |

A remote image must stay reachable while the lesson runs. For reliability, upload it first (section 9.4) and use the
returned `/uploads/…` path.

### 5.4 `media`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `url` | string | required | ≤ 2000. One of: a YouTube link (`youtube.com/watch?v=…`, `youtu.be/…`, `/embed/`, `/shorts/`, `/live/`), a Vimeo link, an `https://` file ending in `.mp4 .webm .ogv .mp3 .ogg .oga .wav .m4a`, or an uploaded `/uploads/…` file with one of those extensions. Anything else is rejected. |
| `kind` | enum | `"video"` | `video` or `audio`. |
| `title` | string | `""` | ≤ 160. |
| `start` | integer | — | 0–86400. Start position in seconds. |
| `phones` | boolean | `false` | Also show the player on phones. Otherwise it plays on the main screen and phones say to watch or listen in the room. |

## 6. Slide types

### 6.1 `content`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `layout` | enum | chosen automatically | `title`, `text`, `image-text`, `full-image`, `instructions`. |
| `title` | string (inline rich text) | `""` | ≤ 160. |
| `body` | string (block rich text) | `""` | ≤ 2500. |
| `steps` | string[] (inline rich text) | `[]` | ≤ 12 steps, each 1–240. Shown as numbered cards. |
| `callout` | object | — | `{ "tone": "info" \| "warning" \| "success", "text" }`. `tone` defaults to `info`; `text` 1–400 (inline rich text). Not shown with the `title` layout. |

Rules:
- At least one of `title`, `body`, `steps` or `image` is required.
- `image-text` and `full-image` need an `image`.
- `instructions` needs `steps` (or a `body`).

When `layout` is omitted it is chosen in this order: only an image → `full-image`; an image with text → `image-text`;
steps → `instructions`; a title with no body → `title`; otherwise `text`.

```json
{ "id": "safety", "type": "content", "layout": "instructions", "title": "Your turn: 10 minutes",
  "steps": ["Fill the squeeze bottle", "Drip ten pearls into the bath", "Lift them out after 45 seconds"],
  "callout": { "tone": "warning", "text": "Wipe up drips at once: alginate is slippery." } }
```

### 6.2 `quiz`

A question with a right answer. `kind` decides how it is answered and which answer key it needs.

**Shared quiz fields**

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `question` | string (inline rich text) | required | 1–300. |
| `kind` | enum | `"single"` | `single`, `multiple`, `match`, `order`, `text`, `numeric`, `hotspot`. |
| `explanation` | string (inline rich text) | `""` | ≤ 500. Shown on the projector and every phone after the reveal. Write one for every quiz. |
| `scored` | boolean | `true` | `false` = practice: never counts towards points or the leaderboard. |
| `points` | integer | `1000` | 10–10000. |
| `speedBonus` | boolean | `false` | Points fall linearly to half at the deadline. Needs `timeLimitSec` and `scored: true`. |
| `partialCredit` | boolean | `true` | `multiple`, `match`, `order` only (see grading, section 8). |
| `concepts` | string[] | — | ≤ 8, each 1–60. Results and insights group correctness by concept. Reuse the same spelling across questions. |
| `branch` | object | — | Section 6.2.8. |
| `view` | — | — | **Never set.** Generated for the audience; setting it is an error. |

Kind-specific fields are listed below. A field that belongs to a different kind is an error (for example `options` on
a `match` question, or `correctOptionId` on a `multiple` question), so a typo in `kind` never silently drops the answer.

#### 6.2.1 `single`: one correct option

| Field | Rules |
| --- | --- |
| `options` | 2–6, each `{ "id", "text", "misconception"? }`. `text` 1–160 (inline rich text). `misconception` ≤ 120: the misunderstanding that leads someone to pick this wrong option; results count how many chose it. |
| `correctOptionId` | Required. Must equal one option `id`. |

People tap one option and it is sent at once. True/false is a `single` question with two options. Up to four options
are shown in one column on the projector; five or six use two columns.

```json
{ "id": "q-ion", "type": "quiz", "question": "Which ion makes the alginate skin set?",
  "options": [
    { "id": "a", "text": "$\\ce{Na+}$", "misconception": "Thinks the sodium in sodium alginate does the setting" },
    { "id": "b", "text": "$\\ce{Ca^2+}$" },
    { "id": "c", "text": "$\\ce{Cl-}$" }
  ],
  "correctOptionId": "b", "timeLimitSec": 25, "speedBonus": true, "concepts": ["Cross-linking"],
  "explanation": "Each $\\ce{Ca^2+}$ carries two charges, so it can hold two alginate chains together." }
```

#### 6.2.2 `multiple`: tick every option that applies

| Field | Rules |
| --- | --- |
| `options` | 2–6, as above (misconceptions allowed). |
| `correctOptionIds` | 1 or more option ids, no duplicates, each must exist. |
| `partialCredit` | Default `true`. |

People tick options, then lock in. The projector shows "Select all that apply".

#### 6.2.3 `match`: connect pairs

| Field | Rules |
| --- | --- |
| `pairs` | 2–6, each `{ "id", "left", "right" }`, both 1–120. Right-hand items must differ from each other (compared ignoring case). |
| `partialCredit` | Default `true`. |

Write the pairs correctly matched; everyone gets the right-hand side shuffled. People connect by tapping or dragging.

```json
{ "id": "q-match", "type": "quiz", "kind": "match", "question": "Match each ingredient to its job",
  "pairs": [
    { "left": "Sodium alginate", "right": "Forms the gel chains" },
    { "left": "Calcium lactate", "right": "Cross-links the chains" },
    { "left": "Clean water", "right": "Stops the skin thickening" }
  ] }
```

#### 6.2.4 `order`: put items in order

| Field | Rules |
| --- | --- |
| `items` | 2–6, each `{ "id", "text" }`, `text` 1–160. **Write them in the correct order.** |
| `partialCredit` | Default `true`. |

Everyone gets the items shuffled and drags or taps them into place.

#### 6.2.5 `text`: a typed answer

| Field | Default | Rules |
| --- | --- | --- |
| `acceptedAnswers` | required | 1–20 strings, each 1–200. List every spelling and form you accept (`"photosynthesis"`, `"photo-synthesis"`). |
| `caseSensitive` | `false` | `true` only when capitals matter (chemical symbols, code). |
| `whitespace` | `"normalize"` | `normalize`: trim and collapse spaces. `ignore`: remove all spaces (formulas, code). `exact`: compare as typed. |

Keep the expected answer short (one word or a short phrase) and say so in the question ("one word").

#### 6.2.6 `numeric`: a number

```json
"numeric": { "value": 2.5, "tolerance": 0.1, "tolerancePercent": 0, "unit": "g" }
```

| Field | Default | Rules |
| --- | --- | --- |
| `numeric.value` | required | A finite number. |
| `numeric.tolerance` | `0` | ≥ 0. Absolute: accepted if within ± this. |
| `numeric.tolerancePercent` | `0` | 0–100. Relative to `value`. The larger of the two tolerances applies. |
| `numeric.unit` | `""` | ≤ 20. Shown beside the answer box; people may type it or leave it off. |

Accepted inputs: `3.5`, `-2`, `1,000` (comma only as a thousands separator in the `1,234,567` pattern, never a
decimal comma), `1e-3`, `3/4`, and the number followed by the unit. Give a tolerance whenever rounding is involved.

#### 6.2.7 `hotspot`: tap the right place on a picture

| Field | Rules |
| --- | --- |
| `image` | Required. Use `"fit": "contain"` so the whole picture, and so every region, is visible. |
| `regions` | 1–10, each `{ "id", "shape", "x", "y", "w", "h", "label" }`. `shape` is `rect` (default) or `ellipse`. `x`, `y` are the top-left corner and `w`, `h` the size, all as fractions 0–1 of the image's width and height; `x + w ≤ 1`, `y + h ≤ 1`, `w` and `h` > 0. `label` ≤ 80, shown after the reveal. |

Regions are in **image** coordinates (0,0 = top-left of the picture, 1,1 = bottom-right), independent of how large it
is shown. An ellipse is the ellipse inscribed in its box. Only author a hotspot question when you know where the
feature is in the picture (for example a picture you drew or measured).

#### 6.2.8 `branch`: suggest where to go next

```json
"branch": { "threshold": 60, "below": "recap-slide-id", "atOrAbove": "next-topic-id" }
```

| Field | Default | Rules |
| --- | --- | --- |
| `threshold` | `60` | 1–100, a percentage of people fully correct. |
| `below` | — | Slide id to suggest when the correct rate is below the threshold. |
| `atOrAbove` | — | Slide id to suggest otherwise. |

At least one of `below` / `atOrAbove` is required; each must be an existing slide id other than this one. In a live
session the dashboard *suggests* the slide and the presenter decides. In self-paced mode the person's own result picks
their next slide. A typical pattern is a recap slide placed right after the question (`below`) and the next new
material after it (`atOrAbove`), so a presenter who ignores the suggestion still sees the recap.

### 6.3 `poll`

No right answer.

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `question` | string (inline rich text) | required | 1–300. |
| `options` | array | required | 2–10, each `{ "id", "text" }`, `text` 1–160. |
| `multiple` | boolean | `false` | Allow several choices. |
| `maxSelections` | integer or `null` | `null` | Only with `multiple: true`; 1 to the number of options. |
| `anonymous` | boolean | `false` | Leave names out of the CSV export. |

### 6.4 `wordcloud`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `question` | string (inline rich text) | required | 1–300 (the prompt). |
| `maxLength` | integer | `40` | 1–100 characters per answer. |
| `maxWords` | integer | `5` | 1–10 words per answer. For a classic one-word cloud use `1` or `2` and say "one word" in the prompt. |
| `maxSubmissions` | integer | `3` | 1–10 answers per person. |
| `moderation` | enum | `"off"` | `off` or `premoderate` (the presenter approves each answer before it shows). |

Answers are grouped ignoring case and punctuation; offensive words are always blocked.

### 6.5 `open`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `question` | string (inline rich text) | required | 1–300. |
| `mode` | enum | `"short"` | `short` (one line) or `paragraph`. |
| `maxLength` | integer | — | 10–2000; at most 280 with `mode: "short"`. |
| `maxSubmissions` | integer | `1` | 1–5. |
| `moderation` | enum | `"off"` | `off` or `premoderate`. |

### 6.6 `rating`

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `question` | string (inline rich text) | required | 1–300. |
| `min` | `0` or `1` | `1` | |
| `max` | integer | `5` | 2–10 and greater than `min`. |
| `minLabel`, `maxLabel` | string | `""` | ≤ 40 each. Always label both ends. |
| `confidenceFor` | string[] | — | ≤ 20 slide ids, each an existing **quiz**. Makes this a confidence check: results compare each person's confidence with whether they got those questions right. |

### 6.7 `survey`

Several questions answered together on one phone screen, submitted once.

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `title` | string | required | 1–200. |
| `description` | string | `""` | ≤ 500. |
| `questions` | array | required | 1–20, ids unique. Each is one of the kinds below. |

| Question `kind` | Fields |
| --- | --- |
| `choice` | `id`, `question` (1–300), `options` (2–10 `{ "id", "text" }`), `multiple` (`false`), `maxSelections` (`null`, only with `multiple`), `required` (`true`) |
| `rating` | `id`, `question`, `min` (`0`/`1`, default `1`), `max` (2–10, default `5`, > `min`), `minLabel`, `maxLabel` (≤ 40), `required` (`true`) |
| `text` | `id`, `question`, `mode` (`short`/`paragraph`), `maxLength` (10–2000, ≤ 280 when short), `required` (**`false`**) |

Written survey answers are shown to the presenter only, never projected.

## 7. Rich text: formatting, maths, code and chemistry

Fields marked *rich text* accept a small, safe Markdown subset with three technical extensions: **maths** (KaTeX),
**code** (syntax highlighting) and **chemistry** (mhchem equations, SMILES structures, reaction schemes). Everything
is parsed into a tree and rendered as text, never as HTML, so nothing can inject markup. The maths, code and chemistry
libraries load only when a slide uses them.

There are two levels:

- **Inline rich text**: content `title`, `steps`, `callout.text`, every `question`, option `text` and `explanation`.
  Formatting, inline maths, inline code, chemical equations and inline structures.
- **Block rich text**: content `body` only. Everything inline, plus paragraphs, lists, tables, display maths, code
  blocks and reaction schemes.

Remember to escape for JSON: every backslash is doubled (`"$\\frac{1}{2}$"`), quotes are `\"`, newlines are `\n`.

### 7.1 Formatting

| Write | Shows | Where |
| --- | --- | --- |
| `**bold**`, `*italic*` | Bold, italic | inline |
| a single line break | A line break | inline |
| a blank line | A new paragraph | body |
| `- item` or `* item` | Bullet list | body |
| `1. item` or `1) item` | Numbered list (may start at any number) | body |
| `\| a \| b \|` then `\|---\|---:\|` then rows | A table. Separator cells: `---` or `:--` left, `--:` right, `:-:` centre. Cells hold inline rich text, including maths and code. | body |
| `\*`, `` \` ``, `\$`, `\\`, `\|`, `\_` | The literal character | inline |

### 7.2 Maths

LaTeX rendered with KaTeX.

| Write | Shows | Where |
| --- | --- | --- |
| `$x^2 + 1$` | Inline maths | inline |
| `$$\int_0^1 x\,dx = \tfrac{1}{2}$$` on its own line | Display maths, centred | body |
| `$$` on a line, several lines of LaTeX, `$$` on a line | Multi-line display maths (`\begin{aligned}…\end{aligned}` works) | body |

- A `$` followed by a space is a literal dollar sign, so "costs $ 5" needs no escaping; write `\$5` for "$5".
- Maths works in quiz options, so an option can be `"$\\frac{3}{4}$"`.
- Answers to maths questions are usually best as `numeric` (exact value with a tolerance) rather than `text`.

```json
{ "type": "quiz", "question": "Solve $2x + 3 = 11$", "kind": "numeric",
  "numeric": { "value": 4 }, "explanation": "$2x = 8$, so $x = 4$." }
```

### 7.3 Code

| Write | Shows | Where |
| --- | --- | --- |
| `` `len(xs)` `` | Inline code (monospace) | inline |
| ```` ```python ```` newline … newline ```` ``` ```` | A code block with syntax highlighting. Indentation and blank lines are kept exactly. `~~~` fences also work. | body |

Highlighted languages: `python` (`py`), `javascript` (`js`), `typescript` (`ts`), `java`, `c`, `cpp` (`c++`), `csharp`
(`c#`, `cs`), `sql`, `bash` (`sh`, `shell`), `json`, `xml` (`html`), `css`, `plaintext` (`text`, `txt`). Any other
label is shown as plain monospace with the label. The language label is shown on the block.

- Code blocks go in a content `body`. Questions and options take inline code only, so ask about a program by showing
  it on a content slide first, then asking in the next slide ("What does the code on the last slide print?"), or quote
  a single line inline.
- For "type the output" questions use `kind: "text"`; for code or formulas where spacing should not matter use
  `"whitespace": "ignore"`, and `"caseSensitive": true` when capitals matter.
- Blocks shrink with the slide to fit the projector; keep them to about 15 short lines so they stay readable.

````json
{ "type": "content", "title": "What does this print?",
  "body": "```python\nfor i in range(3):\n    print(i * 2)\n```" }
````

### 7.4 Chemistry

| Write | Shows | Where |
| --- | --- | --- |
| `$\ce{2H2 + O2 -> 2H2O}$` | Formula or equation (KaTeX mhchem). Arrow conditions: `$\ce{->[NaBH4][MeOH]}$`. | inline |
| `$\pu{25 ^\circ C}$` | Physical units | inline |
| `{{smiles:CC(=O)O}}` | A skeletal structure drawn from SMILES (no spaces inside). An option whose whole text is one structure becomes a large card on the projector and a tile on phones. | inline |
| ```` ```route ```` … ```` ``` ```` | A reaction scheme or synthetic route | body |
| ```` ```smiles ```` … ```` ``` ```` | Structures side by side with captions, no arrows | body |

Inside a `route` block, one item per line:

- a molecule: its SMILES, then an optional caption (`C1=CC=CC=C1 "benzene"`); `?` (optionally with a caption) is a
  dashed box for an unknown;
- an arrow: `-> conditions above | conditions below` (inline markup allowed, such as `$\ce{AlCl3}$`);
- `+`: a plus sign.

Lowercase aromatic SMILES (`c1ccccc1`) draw a ring with a circle; Kekulé form (`C1=CC=CC=C1`) draws alternating double
bonds. Every structure in a scheme uses the same bond length, and bonds follow the text colour on light and dark
projectors. SMILES are not validated on import: an unreadable one is shown as underlined text, so check the preview.

### 7.5 A technical example

A short lesson using maths, code and chemistry together:

```json
{
  "schemaVersion": 1,
  "title": "Rates in three languages",
  "theme": { "palette": "slate", "background": "grid" },
  "slides": [
    {
      "id": "rate-law", "type": "content", "title": "Rate laws",
      "body": "For a first-order reaction:\n\n$$\\ln[A]_t = \\ln[A]_0 - kt$$\n\n| Order | Half-life |\n|:--|:--|\n| 0 | $\\frac{[A]_0}{2k}$ |\n| 1 | $\\frac{\\ln 2}{k}$ |"
    },
    {
```

## 8. How answers are graded

Grading is deterministic: the same answer always gets the same grade, with an explanation. No AI is involved.

| Kind | Correct when | Partial credit (`partialCredit: true`) |
| --- | --- | --- |
| `single` | The chosen option is `correctOptionId`. | — |
| `multiple` | Exactly the `correctOptionIds` are ticked. | (right ticks − wrong ticks) ÷ number of correct options, never below 0. |
| `match` | Every left item is connected to its right item. | Share of left items connected correctly. |
| `order` | Every item is in its position. | Share of positions holding the right item. |
| `text` | After normalising (Unicode NFKC, the `whitespace` rule, and lower-casing unless `caseSensitive`), the answer equals an accepted answer. | — |
| `numeric` | \|answer − value\| ≤ max(`tolerance`, \|value\| × `tolerancePercent` ÷ 100). | — |
| `hotspot` | The tap is inside any region. | — |

**Near misses go to review**, so the presenter decides instead of the answer being marked wrong:

- `text`: within 1 character of an accepted answer (answers of 4–8 characters) or 2 characters (9 or more); a swap of
  two neighbouring letters counts as one. Also a case- or spacing-only difference when the rules ask for exact case or
  spacing.
- `numeric`: within twice the tolerance, or within 1% of the value when there is no tolerance.
- `hotspot`: within 3% of the image outside a region.

Points: a fully correct scored answer earns `points`; partial credit earns that share. With `speedBonus`, points fall
linearly from the full amount to half at the deadline. Only fully correct answers count as "correct" in the
leaderboard and the CSV export; the CSV score column shows partial points.

**What the audience can see.** Phones and the projector never receive answer keys, misconceptions, concepts, branches
or speaker notes before the reveal. Match and order questions are sent shuffled under opaque ids.

## 9. Importing and the API

All Studio routes are under `/api/studio` and need `Authorization: Bearer <token>`.

### 9.1 Get a token

`POST /api/auth/login` with `{ "password": "<studio password>" }` returns `{ "token" }`. When the server has no
Studio password set, any body returns a token.

### 9.2 Create a lesson

`POST /api/studio/presentations/import` with the document as the JSON body (≤ 2 MB).

- `201 { "id": "…", "warnings": ["…"] }`: created. Warnings are informational (for example a missing `schemaVersion`).
- `422`: rejected, nothing saved:

```json
{ "error": { "code": "INVALID_PRESENTATION", "message": "The presentation JSON has problems",
  "details": { "issues": [
    { "path": "slides[2].correctOptionId", "message": "\"correctOptionId\" (\"e\") does not match any option. Valid ids: a, b, c, d", "slide": 2 },
    { "path": "slides[4].timelimit", "message": "Unknown field \"timelimit\" in slides[4]. Did you mean \"timeLimitSec\"?", "slide": 4 }
  ] } } }
```

Every problem is reported at once. `slide` is the zero-based slide index (or `null`). Fix them all and send again.

### 9.3 Read, update, export

| Route | Does |
| --- | --- |
| `GET /api/studio/presentations` | List presentations. |
| `GET /api/studio/presentations/:id` | Get one (`{ doc, … }`). |
| `PUT /api/studio/presentations/:id` | Replace the whole document (same body and validation as import; slides are matched by `id`, so keep ids stable when editing). |
| `GET /api/studio/presentations/:id/export` | The canonical JSON, with every default written out. |
| `POST /api/studio/presentations/:id/duplicate` | Copy. |
| `DELETE /api/studio/presentations/:id` | Delete. |
| `GET /api/studio/templates`, `POST /api/studio/templates/:id` | List the starter templates; create a lesson from one. |
| `GET /api/schema/presentation.json` | The JSON Schema (no sign-in). |

### 9.4 Uploading pictures and media

Send the file's bytes as the request body with its content type; the response is `201 { "url": "/uploads/…" }`.
Use that `url` in `image.url`, `theme.logo.url` or `media.url`.

| Route | Content types | Limit |
| --- | --- | --- |
| `POST /api/studio/uploads` | `image/png`, `image/jpeg`, `image/gif`, `image/webp` (SVG is refused) | 5 MB |
| `POST /api/studio/uploads/media` | `video/mp4`, `video/webm`, `audio/mpeg` (MP3), `audio/mp4` or `audio/x-m4a` (M4A), `audio/webm`, `audio/ogg`, `audio/wav` or `audio/x-wav` | 25 MB |

Files are checked by their contents, not just the declared type.

### 9.5 Check it before class

- Start a **rehearsal**: `POST /api/studio/presentations/:id/rehearse` with `{ "participants": 12 }` creates a private
  session in which simulated people answer every activity, kept out of results and reports. Or use **Preview** in the
  editor, which shows every slide on the projector and a phone with sample answers.
- Export and diff: `import → export → import → export` produces identical JSON.

### 9.6 Ids, defaults and round trips

Import fills in missing ids and defaults. Export writes every default out, except fields that cannot apply to a quiz's
kind (such as `correctOptionIds` on a single-answer question), so a document's meaning never depends on defaults that
might change later. Writing defaults yourself is allowed but not needed.

## 10. Writing a good lesson (guidance for agents)

These are recommendations, not validation rules.

**Shape**
- Open with a `content` title slide (an `image` and a one-line promise of what people will do), then an easy warm-up
  activity (a `wordcloud` or `poll`) so every phone is connected before anything is scored.
- Alternate: one or two content slides, then an activity. Aim for an activity every 3–5 minutes of teaching.
- End with a confidence `rating` linked to the key questions (`confidenceFor`), an `open` question for what is still
  unclear, and optionally a short `survey`.
- Keep a lesson to roughly 10–25 slides for an hour.

**Content slides**
- One idea per slide. Prefer `steps` for procedures and a `callout` for safety or the key takeaway.
- Bodies of 1–4 short paragraphs or 3–6 bullets. Text shrinks to fit, but large text reads better across a room.
- Put the detail you would say aloud into `notes`, not onto the slide.

**Questions**
- Use the kind that matches the thinking: `single` for recognition, `multiple` for "which of these", `order` for
  sequences and methods, `match` for vocabulary and relationships, `numeric` for calculations, `text` for recall of a
  term, `hotspot` for "where on this diagram".
- Write plausible wrong options that reflect real misunderstandings, and record each one in `misconception`.
- Always write an `explanation`: it is what people read on their phone after the reveal.
- Tag each question with 1–3 `concepts`, spelled identically across the lesson.
- Use `timeLimitSec` of 20–45 for recall, 45–120 for calculations; only add `speedBonus` for fast recall rounds.
- Use `scored: false` for diagnostic or practice questions.
- For `text`, list every reasonable spelling in `acceptedAnswers`; for `numeric`, set a tolerance whenever rounding
  is involved.
- After a key question, add a recap slide and a `branch` pointing `below` at it.

**Accessibility and safety**
- Write `alt` for every image. Don't put essential text only inside a picture.
- Keep prompts age-appropriate and avoid asking for personal information in `open` questions; use
  `moderation: "premoderate"` when answers will be projected to a young audience.

## 11. Self-check before submitting

- [ ] Top level has `schemaVersion: 1`, `title` and `slides`, and nothing else besides `format`, `description`, `theme`.
- [ ] Every slide has a valid `type`; ids are unique and set explicitly where referenced.
- [ ] No unknown fields; field names match this document exactly.
- [ ] Every quiz has the answer key for its `kind`, and no fields from other kinds.
- [ ] `correctOptionId` / `correctOptionIds` match option ids; `order` items are in the correct order.
- [ ] `speedBonus` only with `timeLimitSec` and `scored: true`.
- [ ] `branch` targets and `confidenceFor` ids exist (`confidenceFor` only lists quizzes).
- [ ] Hotspot regions stay inside the image (`x + w ≤ 1`, `y + h ≤ 1`) and the image uses `"fit": "contain"`.
- [ ] Backslashes in maths and chemistry are doubled in JSON.
- [ ] Every image has `alt`, and every quiz has an `explanation`.
- [ ] All lengths and counts are inside the limits.

## 13. Versioning

Documents carry `schemaVersion`. This specification describes version **1**. When the schema changes, the importer
ships a migration from older versions, so documents written to this specification keep working. A document with a
newer version than the server supports is rejected with a message asking to update ClassInteract.
